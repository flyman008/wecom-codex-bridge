# 安装配置项

仓库只提供能力和安全边界，不携带发布者的个人偏好。模型能力由使用者已登录的 Codex 提供，不需要第二套模型服务。首次安装运行：

```bash
npm run setup
```

## 必须由使用者决定

| 决策 | 可选方式 | 保存位置 |
| --- | --- | --- |
| 机器人人设 | 专业简洁 / 温和简洁 / 完全自定义 | `.runtime/persona-profile.json` |
| 偏题提醒 | 关闭 / 自定义次数和文案 | 人设文件 |
| Codex 模型 | 指定首选与备用 / 留空继承 Codex | `.env` |
| 推理与速度 | 指定强度和 Fast / 留空继承 Codex | `.env` |
| 文件权限 | 只读 / 授权目录可写 | `.env` |
| 会话上下文 | 持久会话 / 每次独立 | `.env` |
| 登录后自启动 | 开启 / 关闭 | `.env` 与操作系统用户启动项 |

所有消息都直接进入使用者已登录的 Codex CLI。企微文档转换要求由本地关键词规则识别，不调用额外模型。

Codex CLI 本身需要有效账号。可以运行 `codex login` 使用 ChatGPT 账号，也可以按 Codex 官方方式使用 OpenAI API Key；登录凭证不保存在本项目的 `.env` 中。

## 可继承 Codex 的项目

`CODEX_MODEL`、`CODEX_REASONING_EFFORT` 和 `CODEX_SERVICE_TIER` 留空时，桥接服务不会覆盖使用者当前的 Codex 配置。备用模型留空时不自动降级。

模型是否可用、支持哪些推理强度或速度档位，取决于使用者的 Codex 版本、账号和组织策略。配置向导不猜测账号权限。

## 断流恢复

`CODEX_TRANSIENT_RETRIES` 控制 Codex 网络连接或上游响应流临时中断后的同模型续跑次数，默认是 `2`。断流续跑不会切换备用模型；只有额度、配额或限流错误才按备用模型策略处理。最终仍失败时，服务会同时结束原流式回复并主动发送失败通知，避免企业微信确认结束帧但客户端未展示。

## 重新配置

再次运行 `npm run setup` 会以现有本机配置为起点。Bot Secret 留空时保留原值；其他项目可以重新选择。

修改自启动选择后执行：

```bash
npm run autostart:apply
```

`false` 会移除当前仓库实例对应的用户级自启动项，但不会停止已手动启动的服务。启动项名称包含仓库路径哈希，因此不会误删同一台机器上的其他部署实例。
